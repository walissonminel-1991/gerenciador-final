# GERENCIADOR FINAL — D2.1: HTTP simulado, bytes inertes

Escopo: testar a interface de uma resposta HTTP simulada em memória e entregá-la ao **gravador D2 já aprovado**. Não existe conexão de rede: `SimulatedResponse` usa somente `BytesIO`; `StrictSimulatedHttpSource` não possui acesso a sockets. A função `verify_d0_tuf` de D2 reutiliza o parser C# D0 de Release fictícia e os metadados TUF **assinados apenas com seeds públicas de laboratório**.

A fonte aceita apenas a URL canônica da fixture, status 200, ausência de qualquer redirecionamento, cabeçalhos `Content-Type: application/octet-stream` e `Content-Length` único, decimal, exato e dentro do orçamento. Rejeita campos adicionais, duplicações com caixa diferente, codificação/transferência inesperada, corpo incompleto/excedente, falhas de leitura e dados alterados. O D2 grava somente bytes inertes e relê o SHA-256 antes e após renomear para um nome fixo dentro de `RUNNER_TEMP`.

**Limites obrigatórios:** isso não testa TLS, sockets, bibliotecas HTTP reais, transferência HTTP/2, redirecionamentos legítimos do GitHub para infraestrutura de assets, CDN, download parcial, suporte a recomeço, durabilidade por crash nem contenção TOCTOU/NTFS contra o mesmo usuário. Um cliente que recuse todos os redirecionamentos **não serve ainda para baixar Releases reais do GitHub**, que frequentemente redirecionam os assets: a política de destinos intermediários deve ser definida separadamente e os bytes autenticados antes de qualquer uso. Zero código do GF distribuído, zero instaladores, zero chaves privadas operacionais. H1 permanece sem prova, assim como READY e G1–G8.
